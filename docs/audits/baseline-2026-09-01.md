## Mock versus real boundary

| Capability | Baseline implementation | Production authority |
| --- | --- | --- |
| Authentication | `AuthContext`, hard-coded flow and browser storage | none |
| Session | browser `localStorage` | none |
| Catalog/search | in-repository arrays and mock API helpers | none |
| Cart | browser state and `localStorage` | intentionally untrusted |
| Pricing/checkout | client-side arithmetic | none |
| Orders/tracking | browser state, hard-coded IDs/statuses | none |
| Payment | simulated timeout/alerts | none |
| Operator authorization | unavailable | none |
| Database/RLS | unavailable | none |

The baseline UI is therefore a browser prototype, not a production backend.
The modernization must preserve useful UI behavior while moving every sensitive
decision to the server and database boundaries.
